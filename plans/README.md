## Direction findings (options for the maintainer, not ranked against bugs)

- **DIR-01 — Open (or explicitly close) the third-party tweak marketplace.** The rails are built and unused: `tweak-store.ts` supports `{kind:"remote", repo, approvedCommitSha}` with SHA-pinned archive installs, yet `store/index.json` has 0 remote entries and publishing is a manual admin loop. Trade-off: opening it multiplies untrusted-code review load (see finding 15). Effort L (process/UX, not core code). Suggested first step: one real remote entry end-to-end as a spike.
- **DIR-02 — Extract the user-questions MCP broker into a reusable SDK helper.** Any tweak can declare an MCP server in its manifest, but the renderer-form/broker machinery that makes one useful is trapped in `tweaks/user-questions` (11 test files deep). A `@tweakers/mcp` helper makes "tweak as MCP tool" near-free (AppShots-as-a-tool, project switching). Effort L; risk: must not weaken user-questions' fail-closed semantics. Design-spike plan, not a build plan.
- **DIR-03 — Ship or retire `plans/dock-icon-customizer.md`.** A fully-researched plan (host selector located, route chosen) marked "not started" since 2026-07-17; no `co.tweakers.dock-icon` exists. Either execute it (good native-bridge showcase) or delete it so it stops reading as a promise.
- **DIR-04 — Make `tweaker tweaks` real.** `cli.ts:457` promises "List and manage installed tweaks" and prints one static sentence. State already on disk; S–M effort for list/enable/disable, reusing runtime helpers to avoid a second state writer (coordinate with Plan 003's funnel).
- **DIR-05 — Settings/tweak-selection export & import.** Only recovery path today is `uninstall --purge` (destroys everything). A versioned export bundle de-risks the exact scenarios TROUBLESHOOTING.md spends most of its length on. M effort; decide scope (settings only vs tweak-data).
- **DIR-06 — Decide the Windows story.** Advertised (install.ps1, docs, schtasks watcher) but core flows hard-throw macOS-only (`install.ts:466,1838,2954`; native bridge is Obj-C++ only; `integrity.ts:24` carries the PE-resources TODO). Near-term S: mark Windows experimental in README with the unsupported-command list. Parity is a real L project gated on the integrity TODO.

## Findings considered and rejected

- **Lowering the AppShots `minRuntime` pin to `>=1.0.0`** (this packet's own earlier draft of plan 005): rejected — tag v1.0.0 contains neither AppShots nor its APIs, so the lowered pin would falsely claim compatibility with the released runtime. Superseded by the version-governance bump.
- **Mandatory SHA256SUMS as full supply-chain protection** (plan 002 framing): the checksum lives in the same GitHub release as the tarball, so it cannot defend against a compromised release publisher — it closes the missing/corrupt-asset and silent-downgrade failure modes only. Real authenticity needs a detached signature with an externally anchored key (explicit follow-up in plan 002).
- **In-process state serialization as full config.json correctness** (plan 003 framing): `config.json` is co-owned by the installer (`packages/installer/src/config.ts:4`); cross-process lost updates remain possible and are documented as an accepted limitation with the unknown-key round-trip invariant tested.

- **Electron/extract-zip npm-audit highs**: devDependency of `packages/runtime` only; the shipped artifact runs on the host Codex app's Electron, and `extract-zip` runs at npm-install time only. Not reachable in distribution. Bump when convenient (finding 22's cleanup bundle can carry it).
- **"Malicious tweak can do X" class**: tweaks are documented as trusted local code (README Security, SECURITY.md); the boundary claims that *are* made (native-path confinement via `realpathSync` in `native-paths.ts`, no silent tweak updates, 0600 MCP socket with nonce handshake) were verified and hold. The one doc/impl gap is finding 15.
- **curl|bash distribution**: documented, conventional. Hardening note (pin to release tags + checksum) folded into Plan 002's maintenance notes rather than a standalone finding.
- **launchd watcher as persistence surface**: inherent to a user-level LaunchAgent and by design; the meaningful mitigation is Plan 002 (verified content in the tree the watcher executes).
- **Watcher wake cadence, settings-injector observer scheduling, `readState` per-call cost in isolation**: checked, already reasonable or sub-threshold (the last is folded into Plan 003's maintenance note).
- **Dead `??` fallback in `environment-warm-commit.ts:1204-1208`** (exit code dropped from spawn diagnostics): real but message-only; too small for a plan — worth a drive-by fix whenever that file is next touched.
- **`plans/`+`advisor-plans/` as cruft**: kept — they are live planning artifacts (this file reconciles them). The unrelated `rhoslc-*.json` cross-project files are genuinely removable (finding 22).
- **Lockfile drift, abandoned deps on the signing path, AGENTS.md command accuracy**: checked clean — no drift, `@electron/asar`/`tar`/`plist` all maintained, every AGENTS.md command exists.
